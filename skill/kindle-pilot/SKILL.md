# Kindle Pilot

当用户把 Kindle 纳入当前任务并通过 USB 连接电脑时，使用这个 Skill。它的目标是让用户用一句话启动，Agent 在每个需要触屏的节点暂停，收到用户的观察结果后从已保存状态继续。

先定位 Kindle Pilot 仓库；单独安装了 Skill 但缺少工具时，读取或克隆 https://github.com/gaofeng21cn/kindle-pilot ，从仓库根目录运行工具。已有越狱设备的集合任务直接进入集合工作流，不重复越狱和阅读环境安装。

通过 Codex 插件安装时，Skill、`src/`、`scripts/` 和兼容清单位于同一插件根目录；从当前 `SKILL.md` 向上两级定位根目录，优先使用这份已安装字节。`PYTHONPATH=src python3 -m kindle_companion --json software-info` 可只读核对 Package ID、显示名称和版本。安装、更新、启停与卸载交给宿主插件管理器；软件存在不代表 Kindle 已连接或某个业务步骤已完成。

## 一句话入口

用户可以直接说：

~~~text
请使用 $kindle-pilot 管理我当前连接的 Kindle：先识别型号、固件和 USB 状态，选择准确兼容路线；如果支持，就下载并校验官方材料，使用单一 MTP 会话传输；保留原生 Kindle 图书馆，同时配置本地图书、微信读书和番茄小说；在我完成 Kindle 屏幕上的必要步骤后继续，持续推进但不要重复已完成步骤，最后逐项回读验收。
~~~

如果用户只说“已连接”“继续”或“我重新插拔了”，读取已有状态并继续当前流程，不要从头假设，也不要把连接可见当成写入成功。常见的人工续接消息包括：

- "已连接"：重新做只读 USB 探测并回读设备身份。
- "我已完成字体设置"：用户的明确完成消息就是相应观察结果；信息足够时记录 `font_calibration` 并继续。
- "Véra 已打开，正在重启"：等待用户确认 `JAILBROKEN`，不要提前记录越狱完成。
- "JAILBROKEN 已出现"：确认 KPM 是否可用，再进入 KOReader 安装。
- "扫码成功"：分别验证微信读书或番茄小说的账号书架/代表性书籍，不把二维码显示当成登录成功。

## 证据边界

始终区分以下状态：

1. USB 可见，只证明 macOS 发现了设备。
2. 路线支持，需要精确型号和完整固件构建号。
3. 资产摘要匹配，只证明本机文件与清单一致。
4. MTP 写入成功并回读，需要检查远端路径、字节数和存储空间；进程退出码为 0 不足以证明传输成功。
5. 应用加载，需要重启并观察 KOReader / 插件实际出现。
6. 账号或书籍行为验证，需要用户完成扫码并打开真实书籍。

读取 `manifests/compatibility.json` 后再做路线判断。不要把相邻固件、博客教程或旧下载链接当成当前支持路线。新型号或新固件缺少官方 URL、精确 SHA-256、人工交接点或测试时，停在路线选择并说明缺口。

## Agent 自动完成

在用户授权的当前设备范围内，Agent 应持续完成这些主机侧工作：

1. 运行只读 USB 探测，读取产品名和序列号，并要求用户提供设备信息中的完整固件版本（若主机无法读取）。
2. 依据清单选择精确路线；不支持时停止写入并报告原因。
3. 下载清单声明的上游材料，验证 SHA-256，并把私有文件放进未跟踪目录。
4. 生成明确的 MTP 计划，保持一个 OpenMTP 客户端和一个传输批次；处理路径空格，完成后回读远端文件和可用空间。
5. 在越狱已确认且 KOReader 已可用后，按清单安装月读和 `kindle.koplugin`，检查 `koreader/plugins/` 下的实际目录。
6. 将每个已观察步骤写入状态，并在下一次用户消息到来时从状态继续。

使用 `PYTHONPATH=src python3 -m kindle_companion` 做主机侧检查，使用 `scripts/kindle-mtp.py` 或 `kindle_companion.mtp.MtpClient` 进行 OpenMTP 操作。

## 保留给用户的动作

以下步骤必须由用户在设备或手机上完成，Agent 只能清楚引导和记录观察结果：

1. 按 Agent 给出的官方链接打开 Véra 页面；如果路线要求设备端下载，就在 Kindle 浏览器中完成。
2. 完成 Font Calibration 设置并保存。
3. 打开 Véra，等待 `RESTARTING GUI`，再确认 `JAILBROKEN`。
4. 在 Kindle 搜索框执行 KPM 命令并确认 KOReader 能启动。
5. 使用手机完成微信读书、番茄小说等 QR 登录和手机端确认。
6. 打开本地书、Kindle 书库和账号书架中的代表性内容，验证实际阅读行为。

每次暂停都要给出一个具体的下一步和需要用户回报的可观察结果。不要让用户猜测是否该拔线、重启或重复操作。

## 写入和删除保护

执行任何写入前，先读取当前目录和存储信息，展示或记录精确目标。永远不要删除整个 `documents`、`/koreader`、`/libkh`、未知 `.bin` 或未知用户书籍。只处理用户明确识别的临时填充文件、过期更新文件或插件目标，并在操作后回读。

不要把越狱书、设备转储、账号 Cookie、二维码载荷或插件压缩包提交到 Git。资产只从清单声明的上游地址获取并校验。

## 原生集合与漫画管理

用户要求整理原生图书馆时，读取仓库 `docs/NATIVE_COLLECTIONS.md` 和当前路线的 `native_collections` 配置。月读分类、物理目录和 Kindle 原生集合分别管理，不能互相替代。

使用 `scripts/kindle-collections.py` 的 `stage`、`inspect`、`probe`、`receipt`、`plan-series`。KC 发布包必须先匹配兼容清单 SHA-256；复用其中的纯协议和规划模块，不需要安装 Calibre。设备端使用已校验运行文件的脚本入口，电脑通过一个 MTP 批次交换任务、回执和快照；USB 不能直接执行脚本。用户打开入口后再回读，不让用户反复猜步骤。

当前 Colorsoft 5.20.1.0.2 的创建和新增归属通过独立路径验收，读取清单 `native_collections.additions`，使用 `scripts/kindle-collection-additions.py`。旧 KC 六步路径仍未完整通过，不覆盖 KC 的全量能力记录。是否能创建、能删除、能无线连接分别判断，不能绑定为一个全量开关。

盘点按已索引 UUID 和准确路径匹配本机书籍，区分云端记录、原有集合和系列名无法识别的项目。此固件计数只统计可见合集；未知可见性不能称为损坏。不得因标题相同合并 UUID，也不能自动取消 KXO 订阅、删除边车或搬动推送文件。

优先保留用户已有的来源和主题分组，例如 WNACG。册数较少的漫画放入综合漫画合集，只为较多册或用户重点追的长篇保留独立入口；不要把系列识别结果等量转换成合集。先形成可审阅的目标清单，再按用户已授权范围实施。清理本轮多余合集时，先核对成员已到达目标，再只撤销有创建证据的准确合集 UUID，不删除书籍。

实验测试只用一个新建 `KC-PROBE-*` 集合和一本未归类本机书籍。运行前列出目标和六步动作；先备份并验证，再由 Kindle 本地 `/change` 服务写入，数据库始终只读打开。结果不明时核对原任务及 pending 文件，不重新发新任务。回执中的 `confirmed` 需要与之后的设备快照交叉核对；完整六步、样本文件与边车、原有关系都通过才可更新适配状态。测试残留仅处理本次准确 UUID；设备端未验证的清理优先由用户在原生界面完成。

## 可选无线维护

读取 `docs/WIRELESS_MAINTENANCE.md` 和 `wireless_maintenance`。用 `scripts/kindle-wireless.py prepare` 每次重新探测 Mac 网卡与地址、生成临时密钥和会话材料；`transfer` 逐文件 MTP 回读。用户拔线后打开无线入口，再 `connect` 或在明确私有子网内 `discover`。连接必须核对固定服务器公钥、设备摘要、固件和 Dropbear。密钥及设备记录留在忽略目录；不输出私钥、账号令牌。

会话只允许本次主机来源、禁密码及转发、默认 30 分钟自动关闭；完成后主动 `stop` 并回读停止状态。换网络、换主机、组件或固件变化时重新准备，不沿用写死 IP。无线通道可用不自动授权任意书库写入或其他型号。
